# KASU Sound — 演劇本番用 音響再生アプリ

Chromebook で動く、**オフライン前提**の効果音・BGM 再生アプリです。
Google Drive から音源を取り込み、端末内に保存して、本番中はネット接続なしで再生します。

## 1. なぜ Web アプリ（PWA）なのか

| 方式 | 判定 | 理由 |
|---|:--:|---|
| **PWA（Chrome 上の Web アプリ）** | ✅ | Chrome の音声出力は OS へほぼ直結。Web Audio API なら遅延は数 ms〜20 ms 程度。Drive API も公式 JS でそのまま使える。オフラインで起動できる |
| Chromebook の Linux 環境（Crostini） | ❌ | 音声が仮想サウンドデバイス経由になり、遅延・音切れ・機種によっては無音になる。本番での確実性が最も低い |
| Android アプリ | ❌ | 管理環境で Play ストアが制限される可能性。開発・修正のハードルも高い |

「Drive から直接再生するとラグが出る」のは、**再生ボタンを押した瞬間にネットワークへ取りに行っているから**です。
このアプリは構造的にそれを避けます。

## 2. ラグ対策の仕組み

```
■ 仕込み（リハ前に 1 回だけ・ネット接続あり）

   Google Drive ──Picker で選択──> ダウンロード ──> Blob
                                                     │
                                                     ▼
                                           IndexedDB に保存  ← 端末に残る
                                           （消さない限り永久）

■ アプリ起動時（ネット不要）

   IndexedDB ──> decodeAudioData ──> AudioBuffer としてメモリに常駐（待機）

■ 本番

   [▶ 押す] ─> AudioBufferSourceNode.start()  ──> 発音
              ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
              遅延 ≒ 出力バッファのみ（ほぼゼロ）
```

長い曲まで全部メモリに展開すると容量を食うため、**長さで自動的に方式を振り分けます**。

| 長さ | 方式 | 特徴 |
|---|---|---|
| 60 秒以下（既定） | メモリ展開（AudioBuffer） | 遅延ほぼゼロ。効果音向け |
| 60 秒より長い | ストリーミング（先読み済み） | メモリ節約。BGM 向け。読み込みは完了済みなので実用上の遅延は小さい |

境目の秒数は設定画面で変更できます。特定の長い曲を「必ずメモリ展開」にしたい場合は、
そのキューの **読み込み方式** を「メモリ展開」に変えてください。

**音の流れ（同時再生・曲ごと音量・全停止の実現方法）**

```
 キュー01 BGM  ─> Gain（曲ごとの音量／フェード） ─┐
 キュー03 雷SE ─> Gain（曲ごとの音量／フェード） ─┼─> Master ─> スピーカー
 キュー05 拍手 ─> Gain（曲ごとの音量／フェード） ─┘       ↑
                          ↑                        ESC で全部フェード停止
                    それぞれ個別に停止できる
```

## 3. セットアップ手順

所要時間はおよそ **30〜40 分** です。順番どおりに進めてください。

### STEP 1. GitHub Pages で公開する

Drive 連携には **https:// で始まる URL** が必要なので、まず GitHub Pages に置きます。

1. ブラウザで `https://github.com/mostia90/googledrive-is-KASU` を開く
2. このコードは `claude/wonderful-mccarthy-70w16a` ブランチにあります。
   画面上部の緑のバナー、または **Pull requests** タブから `main` ブランチに取り込んでください
   （Pull request を作成 → **Merge pull request** → **Confirm merge**）
3. リポジトリの **Settings**（歯車マーク）をクリック
4. 左メニューの **Pages** をクリック
5. **Source** を `Deploy from a branch` にする
6. **Branch** で `main` を選び、フォルダは `/ (root)` のまま **Save**
7. 1〜3 分待ってページを再読み込みすると、上部に公開 URL が表示されます

   ```
   https://mostia90.github.io/googledrive-is-KASU/
   ```

   **この URL を控えてください。** 以降 `<あなたのURL>` と書きます。

> ℹ️ リポジトリが Private だと GitHub Pages が使えない場合があります。
> その場合は **Settings → 一番下の Danger Zone → Change visibility → Public** にしてください。
> 公開されるのはアプリのコードだけで、**音源はアップロードされません**。

この時点で `<あなたのURL>` を開けばアプリは動きます（ローカルのファイルをドラッグ＆ドロップすれば再生できます）。
Drive 連携を使うには次の STEP 2 が必要です。

### STEP 2. Google Cloud の設定

Drive から取り込むための「鍵」を 2 つ（**クライアント ID** と **API キー**）作ります。
無料です。クレジットカードの登録も不要です。

#### 2-1. プロジェクトを作る

1. `https://console.cloud.google.com/` を開き、**自分の Google アカウント**でログイン
2. 画面上部（Google Cloud ロゴの右）の**プロジェクト選択ボタン**をクリック
3. 右上の **新しいプロジェクト** をクリック
4. プロジェクト名に `kasu-sound` と入力 → **作成**
5. 作成後、もう一度プロジェクト選択ボタンを押し、`kasu-sound` を選ぶ
   （以降の作業はすべてこのプロジェクト内で行います）

#### 2-2. 必要な API を 2 つ有効にする

1. 左上の **≡（ハンバーガーメニュー）** → **API とサービス** → **ライブラリ**
2. 検索欄に `Google Drive API` と入力 → 出てきたものをクリック → **有効にする**
3. もう一度 **ライブラリ** に戻り、`Google Picker API` を検索 → クリック → **有効にする**

#### 2-3. OAuth 同意画面（ログイン画面）を設定する

1. **≡** → **API とサービス** → **OAuth 同意画面**
   （新しい画面では **Google Auth Platform** と表示されます）
2. **開始** または **アプリを構成** をクリック
3. 次のように入力します

   | 項目 | 入力内容 |
   |---|---|
   | アプリ名 | `KASU Sound` |
   | ユーザーサポートメール | 自分のメールアドレスを選択 |
   | 対象（Audience） | **外部** を選択 |
   | 連絡先メールアドレス | 自分のメールアドレス |

4. 利用規約に同意して **作成**

#### 2-4. スコープ（アクセス範囲）を追加する

1. 左メニューの **データアクセス**（旧 UI では「スコープ」）をクリック
2. **スコープを追加または削除** をクリック
3. 右上のフィルタ欄に `drive.file` と入力して検索
4. `.../auth/drive.file` の左のチェックボックスを **ON**
5. 下の **更新** → **保存**

> ℹ️ `drive.file` は「アプリで選んだファイルだけ」にアクセスする**非機密スコープ**です。
> Google の審査は不要で、「このアプリは確認されていません」という警告画面も出ません。

#### 2-5. 自分をテストユーザーに追加する

1. 左メニューの **対象**（Audience）をクリック
2. **テストユーザー** の欄で **+ ユーザーを追加**
3. 自分の Gmail アドレスを入力して **保存**

> 「公開ステータス」が **テスト** のままで問題ありません。
> （`drive.file` だけなら **アプリを公開** を押しても審査は不要です。どちらでも動きます）

#### 2-6. OAuth クライアント ID を作る

1. 左メニューの **クライアント**（旧 UI では「認証情報」）をクリック
2. **+ クライアントを作成** をクリック
3. **アプリケーションの種類** で **ウェブ アプリケーション** を選ぶ
4. 名前は `kasu-sound-web` など任意
5. **承認済みの JavaScript 生成元** の **+ URI を追加** をクリックし、次を入力

   ```
   https://mostia90.github.io
   ```

   ⚠️ **末尾にスラッシュやリポジトリ名を付けないでください。** ドメインだけです。

6. **承認済みのリダイレクト URI** は**空のまま**で構いません
7. **作成** をクリック
8. 表示される **クライアント ID**（`〜.apps.googleusercontent.com`）を**コピーして控える**

#### 2-7. API キーを作る

1. **≡** → **API とサービス** → **認証情報**
2. 上部の **+ 認証情報を作成** → **API キー**
3. 表示された **API キー**（`AIza〜`）を**コピーして控える**
4. （推奨）**キーを制限** をクリックし、次を設定して **保存**

   | 項目 | 設定 |
   |---|---|
   | アプリケーションの制限 | **ウェブサイト** |
   | ウェブサイトの制限 → 追加 | `https://mostia90.github.io/*` |
   | API の制限 | **キーを制限** → `Google Picker API` にチェック |

---

### STEP 3. アプリに設定を貼り付ける

1. Chromebook の Chrome で `<あなたのURL>` を開く
2. 右上の **⚙ 設定** をクリック
3. **Google Drive 連携** の欄に、STEP 2 で控えた値を貼り付ける
   - **OAuth クライアント ID** ← 2-6 でコピーしたもの
   - **API キー** ← 2-7 でコピーしたもの
4. 入力欄の外をクリックすると自動で保存されます。**閉じる**
5. **Driveから取り込み** をクリック
6. Google のログイン画面が出るので、音源が入っているアカウントでログインし、**続行**
7. ファイル選択画面（Picker）が開くので、使う音源を選ぶ（Ctrl キーで複数選択可）
8. 「取り込みました」と出れば完了。以後この音源は**ネットなしで再生できます**

> アプリ ID（プロジェクト番号）はクライアント ID から自動で判定するので、入力は不要です。

---

### STEP 4. Chromebook にインストールする

ブラウザのタブのままでも動きますが、**アプリとしてインストール**したほうが安全です
（タブを間違えて閉じる事故を防げます）。

1. `<あなたのURL>` を Chrome で開く
2. アドレスバーの右端にある **インストール**（⊕ や画面のようなアイコン）をクリック
3. **インストール** をクリック
4. ランチャー（○ボタン）に「KASU Sound」が追加されます。以後はここから起動

#### 保存領域を保護する（重要）

1. アプリを開き **⚙ 設定** → **ストレージ**
2. **保存領域を保護する** をクリック

Chrome が空き容量不足のときに音源を自動削除しないようにする設定です。**必ず実行してください。**

## 4. 使い方

### 画面

```
┌────────────────────────────────────────────────────────────────┐
│ KASU Sound   ●オフライン準備OK(12/12)   [Driveから取り込み] [⚙] │
├─────────────────┬──────────────────────────────────────────────┤
│ キューリスト     │  NOW PLAYING                                 │
│  01 客入れBGM   │   ▶ 02 開演BGM           01:23 / 03:40       │
│ ▶02 開演BGM  ◀今 │   ━━━━━━━━●──────────────                   │
│ ▸03 雷SE    ◀次 │   音量 ━━━━━━●───── 80%    [停止] [フェード] │
│  04 電話の音     │  ──────────────────────────────────────────  │
│  05 拍手SE      │  再生中（同時） ・02 開演BGM  ・03 雷SE       │
├─────────────────┴──────────────────────────────────────────────┤
│ NEXT ▸ 03 雷SE    [SPACE]次を再生   [ESC]全停止   自動再生:OFF  │
└────────────────────────────────────────────────────────────────┘
```

### キーボード操作

| キー | 動作 |
|---|---|
| **Space** | NEXT のキューを再生して、次へ進む（本番中の基本操作） |
| **Esc** | **全停止**（ごく短いフェードでノイズなく止める） |
| **↑ / ↓** | NEXT を 1 つ上／下へ動かす |
| **Home** | NEXT を先頭に戻す |
| **Enter** | 選択中のキューを再生（順番は進めない） |
| **F** | いま鳴っている音をフェードアウト |

### 基本の流れ

1. **音源を取り込む** — 「Driveから取り込み」、または画面にファイルをドラッグ＆ドロップ
2. **並べる** — キューをドラッグ、または `↑` `↓` ボタンで上演順に並べ替え
3. **調整する** — キューをクリックして、音量・フェードイン・フェードアウトを設定
4. **本番** — `Space` で 1 つずつ送り出す。重ねたい音は `Space` を続けて押せば重なる

### 自動再生の ON / OFF

画面右下の **自動再生** チェックボックス（または設定画面）で切り替えます。

- **OFF（推奨）** … キューをクリックしても鳴らない。`Space` を押したときだけ鳴る
- **ON** … キューをクリックした瞬間／取り込んだ瞬間に鳴る

設定はアプリを閉じても保持されます。

### 保存・持ち出し

設定画面の **保存・持ち出し** から使えます。

| 種類 | 内容 | 用途 |
|---|---|---|
| **バックアップ（音源込み）** `.kasupack` | 音源＋並び順＋音量＋フェード＋設定 | 別の Chromebook に丸ごと移す／本番前のバックアップ |
| **設定だけ** `.json` | 並び順・音量・フェードなど（軽い） | 同じ音源がある端末で、リハーサル時の状態を再現 |

> **予備機を用意する場合**：本番機で `.kasupack` を書き出し、予備機で読み込めば同じ状態になります。
> USB メモリに入れておくと安心です。

### 前日まで

- [ ] 全音源を取り込み、バッジが **「オフライン準備OK n/n」（緑）** になっている
- [ ] 設定 → ストレージ → **保存領域を保護する** を実行済み
- [ ] 上演順どおりにキューが並んでいる

### 本番当日・開演前

- [ ] **Wi-Fi を切って**アプリを起動し、全キューが鳴ることを確認（最重要）
- [ ] Chromebook の電源設定 → **画面を自動でオフにしない／スリープしない**
- [ ] 電源アダプタを接続（バッテリー駆動にしない）
- [ ] Chromebook 本体の音量を固定（本番中は触らない。調整はミキサー側で）
- [ ] 出力先が正しいか確認（クイック設定 → 音量の横の「>」で出力デバイスを確認）
- [ ] 通知を切る（クイック設定 → **サイレント モード** を ON）
- [ ] `Space` と `Esc` の動作を実際に押して確認
- [ ] NEXT が 1 番目のキューを指している（`Home` キーで先頭に戻る）
- [ ] 予備機にも同じ `.kasupack` を入れてある

### 本番中に何か起きたら

- [ ] 音が止まらない → **`Esc`**
- [ ] 順番を飛ばしたい → キューを直接クリックしてから `Space`
- [ ] 間違って進めた → `↑` で NEXT を戻す

## 6. 困ったときは

| 症状 | 対処 |
|---|---|
| バッジが赤い「準備できていません」 | 音源が消えています。`.kasupack` から復元するか、再度取り込んでください |
| 「Driveから取り込み」で `redirect_uri_mismatch` / `origin` エラー | STEP 2-6 の **承認済みの JavaScript 生成元** が `https://mostia90.github.io`（末尾スラッシュなし）になっているか確認 |
| Picker が真っ白 / 開かない | STEP 2-2 で **Google Picker API** を有効にしたか、API キーの制限が厳しすぎないかを確認 |
| ログイン時に「アクセスをブロック」と出る | STEP 2-5 でテストユーザーに自分のアドレスを追加したか確認 |
| 音が出ない | Chromebook の出力先（HDMI / イヤホン / 内蔵）を確認。画面のどこかを 1 回クリックしてから再生 |
| 再生が少し遅れる | そのキューの **読み込み方式** を「メモリ展開」に変更してください |
| 設定を変えたのに反映されない | 設定 → ストレージ → **アプリを更新** を押す |
| 音源を全部やり直したい | 設定から `.kasupack` を書き出してバックアップした上で、各キューを削除 |

## 技術メモ（興味があれば）

- フレームワーク不使用。素の HTML / CSS / JavaScript（ES モジュール）
- 音声: Web Audio API（`AudioBufferSourceNode` / `MediaElementAudioSourceNode` + `GainNode`）
- 保存: IndexedDB（メタ情報と音声 Blob を分けて保存）
- オフライン: Service Worker によるアプリシェルのキャッシュ
- Drive: Google Identity Services（トークン）＋ Google Picker、スコープは `drive.file`

| ファイル | 役割 |
|---|---|
| `index.html` / `styles.css` | 画面 |
| `js/main.js` | 画面の組み立て・キーボード操作・全体の制御 |
| `js/audio.js` | 音声エンジン（遅延対策の中心） |
| `js/store.js` | IndexedDB への保存 |
| `js/drive.js` | Google Drive 連携 |
| `js/backup.js` | 保存・読み込み |
| `sw.js` | オフライン動作 |
